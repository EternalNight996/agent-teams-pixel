# 调度与团队配置（极简版）

> 只回答两件事：**从哪里打开调度**、**怎么配置团队**。不加新概念、不做花哨交互，全部复用现有能力。

---

## 1. 从哪里打开调度（入口只有两个）

### 入口 A：会话里一句话（最快）

在任意会话的输入框直接说：

```
/agent-teams 修复登录接口偶发 500，测试在 tests/auth
```

或自然语言：「用团队修复登录接口偶发 500」。
→ 队长生成**计划草案**，右栏自动弹出审批面板。**这是日常最常用入口。**

### 入口 B：右栏「团队协作」（要看/要改时）

会话标题栏右侧 **「查看团队」** → 打开右栏「团队协作」页签：

```
整页 = 山门洞府（谁在跑、谁空闲、谁卡住）
  · 点「山门」= 名册/切换宗门
  · 点「藏经阁」= 道统配置与开宗计划
  · 点「功德碑」= 任务看板与依赖
  · 点「传音阁」= 掌门收件箱
  · 点修士 = 他的会话
上面板/下面板不再常驻：面板是浮层，看完即收，所以洞府始终占满整页
```

页签顶部的 **「开团」一行**（M1 落地，1 天内可做）就是调度入口：

```
团队 [研发核心 ▾]   角色 [前端 × 审查 × 测试 ▾]   目标 [____________]   [开团]
```

- 不选团队/角色 → 直接用「队长 + 默认策略」按目标开团。
- 选好 → 只生成草案，人点「批准」才真正派单（闸门不变）。

> 结论：**入口 A 用来快，入口 B 用来管。** 不需要第三个入口。

## 2. 怎么配置团队（三层，从粗到细）

### 第一层：开团 3 项（必填）

| 字段 | 说明 | 默认 |
|---|---|---|
| 目标 | 一句话，写清验收标准更好 | 无（必填） |
| 团队 | 命名团队/预设；或直接列角色 | 用上次的队伍 |
| 角色 | 成员清单（可从角色库搜索） | 按目标关键词推荐 3–4 个 |

### 第二层：成员级（可选，默认继承队长）

| 字段 | 说明 | 默认 |
|---|---|---|
| 模型 / 思考档 | 成员用哪个模型、reasoning 强度 | 继承队长 |
| 工具策略 | 该成员能用哪些工具（按 id 选预设策略） | 角色对应策略 |
| 执行提示 | 该成员的补充指令（角色卡人格/章节） | 角色卡自动带 |

### 第三层：任务级（模板预填，也可手改）

| 字段 | 说明 | 默认 |
|---|---|---|
| 负责人 | 谁做 | 建议值 |
| 依赖 | 前置任务（DAG） | 模板决定 |
| 验收 / verify | 完成判据、要跑的命令 | 模板占位（自动探测 npm/pytest） |
| 写域 | 允许改哪些路径 | 从目标目录推导 |

### 全局默认（一次配置，长期生效）

`~/.dsh/profiles/desktop/cordis.patch.yml` 的 `agent-teams` 配置：

```yaml
- id: agent-teams
  config:
    maxMembers: 8          # 成员上限（默认 8）
    memberProvider: spawn  # 子代理后端
    memberModel: ''        # 成员默认模型（空=继承队长）
    memberMaxDepth: 0      # 成员不能再开子代理
    toolPolicies:          # 按 id 复用的工具策略
      researcher: { allow: [read, glob, grep] }
```

## 3. 界面上只保留三个动作

```
[开团]  → 出草案（看板自动切换成计划编辑器）
[批准]  → 派单（调度器自动把 ready 任务给空闲成员）
[改]    → 批准前随便改；批准后通过任务/消息改，不重开计划
```

运行中用户只需要看**顶部一行待办**：

```
需要你：批准(1) · 决定阻塞(2) · 交付确认(1)     自动派单：开
```

其它都交给调度器与像素办公室动画，不再要求用户盯任务板。

## 4. 配置放哪里（避免来回找）

| 要改什么 | 去哪改 |
|---|---|
| 这次团队用谁、干什么 | 右栏「开团」一行 / 聊天 `/agent-teams` |
| 某个成员的模型或工具 | 草案里的成员行（点开即改） |
| 任务的验收/命令/写域 | 草案里的任务行（模板已预填） |
| 长期默认（成员上限/默认模型/策略） | profile 的 `cordis.patch.yml`（改完重启） |

**原则**：一次性配置（全局）只放 profile；每次开团的差异只放在草案里。两个地方，不新增第三处。

---

## 5. 用户体验硬规则

1. **三次点击内开团**：开团 → 看草案 → 批准；不需要读文档。
2. **默认值可用**：不填模型/思考档/工具策略也能跑（继承队长 + 角色策略）。
3. **每个默认值可解释**：草案里鼠标悬停显示「为什么选这个角色/负责人」。
4. **失败可见**：生成草案失败或模板探测不到 verify → 明确提示 + 可手改，不静默。
5. **不改聊天流**：调度结果回到聊天（卡片 + 消息），右栏只做管理，不要求用户切换主界面。

## 6. 落地顺序（最小可用）

| 步骤 | 内容 | 时间 |
|---|---|---|
| 1 | ✅ 已实现：会话标题栏「＋ 开团」按钮 + 表单（模板/目标/角色）→ 新建 staged 计划（`/plugins/dsh-agent-teams/quick-start`，复用 `agent_teams_create`，仍需人批准） | 完成 |
| 2 | 团队/角色选择器：先读 `profiles`（命名团队），角色先给固定 29 预设 | 1 天 |
| 3 | 草案里成员/任务行可编辑（复用 StagingPlanEditor） | 1–2 天 |
| 4 | 顶部待办一行（批准/阻塞/交付）+「立即派单」 | 2 天 |
| 5 | 角色库 508 卡接入选择器（最后做） | 3 天 |

**验收**：新用户从打开会话到「批准计划」≤ 3 次点击；不填任何高级字段也能跑通一次小任务。
