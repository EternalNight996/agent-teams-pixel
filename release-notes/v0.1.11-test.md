# v0.1.11-test — active-session resolve fix

## What changed

- **`sessionSnapshot.current` fallback to `items[0]`.** The dsh
  `SessionListSnapshot.current` is masked to `undefined` whenever the active
  session is a subagent child or otherwise not in the plain sidebar list
  (see the type doc: "masked to undefined while its session is off the
  list"). That made `➕ 申请增配`, `🚀 一键组队` and `↻ 恢复运行` all report
  "没有活动会话" even when the user was clearly in a conversation. Both the
  floater and the working-roles tab now fall back to the most recently
  listed session.
- **Three error messages now distinguish the two failure modes** so the
  operator knows what to fix instead of a dead-end alert:
  - `items.length === 0` → "请在 DSH 侧栏新建/选中一个会话"
  - items non-empty but no `current` → "请在 DSH 侧栏选中你要让船长操作的会话"

## Expected

- `➕ 申请增配` posts to `/plugins/agent-teams-pixel/request-help` with the
  resolved session id, and the floater alerts "已向船长发送「人手不足」请求。"
  (or the HTTP-status variant).
- If the sidebar truly has no session, the button now tells the user to
  create / select one rather than a bare "没有活动会话".
