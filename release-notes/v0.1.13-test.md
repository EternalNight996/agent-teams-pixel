# v0.1.13-test — host endpoint 404 fix (real root cause)

## Root cause

`shell.overlay` and `conversation.view` occupants were both confirmed mounted
(`agent-teams-pixel-office` active, `agent-teams-pixel-roles` active), yet the
UI looked empty because **every `/plugins/agent-teams-pixel/*` host endpoint
returned 404**. Tested live: `http://127.0.0.1:5399/plugins/agent-teams-pixel/roles`
→ 404.

Why: the host side registers those routes inside `applyPixelHostLayer →
tryRegister()`, which reads the workspace registry through
`WORKSPACE_KEYS = ['workspaces', 'workspace']`. The real dsh service key is
**`workspaceRegistry`** (confirmed via the host Service catalog). `tryRegister`
never found it, returned `false`, and **registered none of the routes** — so
the client bundle loaded, the components mounted, but their data fetches (roles
/ state / team) all 404'd. That is the "空空如也": mount OK, data missing.

## Changes

- `pixel-integration.ts` `WORKSPACE_KEYS` → `['workspaceRegistry', 'workspaces', 'workspace']`
  (the first key now matches the live service; `index.ts` already used the
  correct `['workspaceRegistry', 'workspace']`).
- **Floater defaults to expanded.** `collapsed` default flipped from `true` to
  `false` in both the client state initializer and the host settings base, so
  the pixel canvas + team list + action buttons are visible on first open
  instead of a bare title bar.

## Install

```sh
gh release download v0.1.13-test --repo EternalNight996/agent-teams-pixel
dsh plugin --profile web add agent-teams-pixel-0.1.13-test.tgz
# restart dsh-desktop (a full restart is required — the host registers routes
# at apply() time, and the key fix only takes effect on a fresh boot)
```

## Verify

After restart, open `http://127.0.0.1:<port>/plugins/agent-teams-pixel/roles`
in the browser — it should now return the JSON role catalog instead of 404.
