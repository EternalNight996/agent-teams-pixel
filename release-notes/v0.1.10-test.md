# v0.1.10-test — client hardening for partial-peer profiles

## What changed

- **`settingsScope` removed from `inject`.** Earlier versions declared it,
  which caused dsh to pend the entire apply() until the settings platform
  plugin arrived. In profiles that don't ship `dsh-client-ui-settings`,
  apply() never fired past `ctx.get('settingsScope')` — the working-roles
  tab and the pixel-office overlay registered nothing. Now `settingsScope`
  is fetched through `ctx.get(...)` with a try/catch; if the service is
  absent the floater still mounts and falls back to hard-coded defaults
  (`collapsed: true, includeArchived: false`).
- **`sessions` softened from hard-required to optional.** The overlay and the
  working-roles tab now both fall through to the `NOOP_SUBSCRIBE` /
  `EMPTY_SNAPSHOT` stubs when `ctx.sessions` is undefined, instead of
  silently unmounting the entire plugin row.
- **Defensive `console.warn` in apply().** Two warnings surface in the
  browser devtools console when a peer is missing: "no slots service" and
  "no sessions service". Lets the operator distinguish "plugin row didn't
  mount" from "tab/overlay is genuinely empty".
- **Host activation wrapped in try/catch.** Any throw inside `applyPixelHostLayer`
  is now caught and logged through `ctx.logger.error` instead of bubbling
  up and aborting the cordis composition. A bad namespace registration or
  route handler no longer blanks the dsh-desktop window.

## Install (this build only — GitHub release)

```sh
# uninstall the npm-installed version if you tried it first
# dsh plugin --profile web remove agent-teams-pixel   # no-op: never registered on npm

# download the test tarball and install from local path
gh release download v0.1.10-test --repo EternalNight996/agent-teams-pixel
dsh plugin --profile web add agent-teams-pixel-0.1.10-test.tgz
```

Or pull the source:

```sh
git clone https://github.com/EternalNight996/agent-teams-pixel.git
git checkout v0.1.10-test
pnpm install --legacy-peer-deps && pnpm build
# then point dsh at the local checkout
dsh plugin --profile web add F:\path\to\agent-teams-pixel
```

## Expected result

After restart:

1. The working-roles tab **renders with the 508-role grid** even if
   settingsScope and sessions are both absent (sessions absence disables
   only the 一键组队 button + the Alt+R jump; the grid itself is fetched
   from the bundled `roles.json` and works offline).
2. The right-side pixel-office floater **renders with an empty team list**
   if sessions is absent; the "暂无团队" placeholder guides the user.
3. `设置 → 像素办公室` **does not appear** if settingsScope is absent
   (expected — that slot requires the settings peer).

## Known still-broken

- `cordis.patch.yml` is still in the **single-element `- insert:` form**
  (matching dsh-agent-teams upstream). The dsh CLI does not auto-merge
  this into the profile. The current workaround is to append the row
  manually to `~/.dsh/profiles/<name>/cordis.patch.yml`:

  ```yaml
  - id: agent-teams-pixel
    config:
      stateDir: .agent-teams
      memberProvider: spawn
      rolesSource: bundled
  - id: ui-agent-teams-pixel
  ```

  We will switch to a top-level array in v0.2.0 once the dsh CLI merge
  semantics are confirmed.
