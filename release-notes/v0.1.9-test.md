# v0.1.9-test — GitHub release candidate

> **Do not install from npm.** Both `agent-teams-pixel@0.1.8` and `@0.1.9` on
> the npm registry are deprecated with a "testing build, please use the
> GitHub release" notice. This v0.1.9-test builds a verified package; once
> it passes the dsh-desktop install smoke, we will bump to v0.2.0 and
> re-publish to npm.

## What to test

1. `git clone` this repo (or unpack the bundle shipped alongside).
2. From the profile directory, install from the local path:
   ```sh
   dsh plugin --profile web add F:\path\to\agent-teams-pixel
   ```
3. Verify the cordis patch is auto-merged into `~/.dsh/profiles/<name>/cordis.patch.yml`. If it isn't, paste this block in manually:
   ```yaml
   - id: agent-teams-pixel
     config:
       stateDir: .agent-teams
       memberProvider: spawn
       rolesSource: bundled
   - id: ui-agent-teams-pixel
   ```
4. Restart `dsh web` (or `dsh-desktop`) and confirm:
   - the right-side floater `🏢 像素办公室` appears
   - the `工作角色` tab shows 508 role cards
   - `设置 → 像素办公室` shows the toggles
5. Press `Alt+O` to toggle the floater, `Alt+R` to jump to the working-roles tab.

## Issues found in v0.1.9 (this test)

- npm deprecated because peer-dependency warnings fired (`@deepseek-ai/cordis`,
  `@deepseek-ai/dsh-llm`, `@deepseek-ai/dsh-tools`). These are marked optional
  in `peerDependenciesMeta` but `pnpm peers check` still flags them. The
  package installs and the bundle registers, but the warning is noise that
  needs a `--no-warn=peer-deps` policy or a `pnpm.allowedDeprecatedVersions`
  line.
- dsh plugin add did not auto-merge the bundled `cordis.patch.yml` into the
  profile's patch layer. This is a dsh tooling question, not the package's
  bug, but the test release will surface whether upstream applies a fix or
  whether we need to ship a `dsh-market` install hook.

## Pass criteria → v0.2.0

When dsh-desktop shows the floater and the working-roles tab after install,
we bump to v0.2.0, un-deprecate on npm, and announce on dshfind.
