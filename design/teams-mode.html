文案即状态机（照搬参考的十态）

任何时刻界面上都必须有一句话解释现状，禁止只显示数字。下面十条是同一份数据在不同局面下的出口。

局面文案触发条件
staged6 项计划等待确认草案已落盘，未创建成员
waitingBreakdown队长正在拆解目标…任务数为 0
allDelivered全部 6 项任务已交付完成数 === 任务数
blockedAndRunning进行中 t3，等待依赖 t5同时有运行与阻塞
running正在执行 t3仅运行
ready就绪待派：t3、t5有就绪任务、无运行
blocked等待依赖：t5全部阻塞
failedSettled2 项失败已结算有失败且未运行
ended已结束团队归档
discarded本次计划已放弃（6 项）草案被丢弃

落点校准（本机 Inspect 实测，不是照抄别人的 slot 名）

参考项目的落点本机实测本设计
conversation.session.header.actions存在 · list · session · replaceRisk none直接采用（会话头入口）
conversation.chat.turnTail存在 · list · session · none直接采用（回合尾卡）
tool.call.toolview存在 · keyed · 开放域 · agents_pixe_* 未占用P1：工具调用渲染成卡片
shell.overlay存在 · list · root · none面板就放这里（已在用）
sidebar.right.pane.tabbody 槽存在，但 sidebarRightTabs 服务不在客户端服务目录改用浮层双栏 + layout.openRightbar()
conversation.chat.nodekeyDomain 被 ChatNodeKind 占满；uiConversation 服务不存在不采用，改用 turnTail + toolview
客户端 inject 里的 uiConversation / modelDirectories本机服务目录只有 8 个：layout / locale / sessions / slots / theme / timer / uiWorkspace / workspaces不声明（声明不存在的服务会让整块静默不挂载）

结论：能抄八成，两条换实现。照抄 slot 名而不做这步校准，结果就是「装上了但什么都不显示，F12 也没线索」。
